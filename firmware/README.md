# On-device energy: ESP32-S3 + Arduino Uno power meter

The ESP32-S3 runs the paper's pipeline (features, then logistic regression) on 8 real CWRU windows stored
in its flash. No accelerometer is needed. An Arduino Uno measures the ESP32's supply current through a
1 Ω shunt resistor, and reads a marker pin that the ESP32 raises while it computes. The result is
**energy per window** for `time_only` vs `envelope_ratio`.

```
                 ┌───────────── Uno 5V ───────────────► ESP32-S3  5V pin
 USB ──► Uno     │                                      ESP32-S3  GND ──┬──► Uno A0
 (Orange Pi      │                                                      │
  or laptop)     │                                                 [1 Ω shunt]
                 └───────────── Uno GND ◄───────────────────────────────┘
                                Uno A1  ◄─────────────── ESP32-S3  GPIO4 (marker)
```

## Parts

- ESP32-S3 dev board (any; PSRAM not needed — the work buffers use about 225 KB of internal RAM)
- Arduino Uno
- 1 Ω resistor, 1%, ¼ W or more (the shunt)
- jumper wires, breadboard
- optional: a multimeter, to measure the Uno's reference voltage and supply (removes the ±10% scale error)

## Wiring

| From | To | Why |
|---|---|---|
| Uno **5V** | ESP32-S3 **5V** pin | powers the ESP32 (it draws ~40–150 mA without Wi-Fi) |
| ESP32-S3 **GND** | one end of the 1 Ω shunt **and** Uno **A0** | A0 reads the voltage across the shunt = current × 1 Ω |
| other end of the shunt | Uno **GND** | the ESP32's current returns through the shunt |
| ESP32-S3 **GPIO4** | Uno **A1** | marker: high while computing |

**Do not connect the ESP32's USB during the power run.** USB would power it around the shunt and the
reading would be wrong. Use USB only for step 2, before wiring.

## Steps

1. **Check the port on your computer** (no hardware): `make device-check`. It compiles the ESP32's DSP code
   for your computer and compares it with the Python reference. Expect `HOST CHECK PASS`.
2. **Flash and check the ESP32-S3** over USB. In the Arduino IDE, select the board *ESP32S3 Dev Module*,
   open `firmware/vibedge_esp32s3/vibedge_esp32s3.ino`, then Upload and open Serial Monitor at 115200. Expect
   `DEVICE CHECK PASS`, timings, then a `cycle …` line every ~20 s. Copy the output into
   `results/real/device_serial.txt`; it is the per-window timing from the ESP32's own clock.
3. **Flash the Uno** with `firmware/uno_power_meter/uno_power_meter.ino`.
4. **Unplug the ESP32's USB** and wire everything as in the table.
5. **Capture** on the machine the Uno is plugged into (Orange Pi or laptop):
   ```
   pip install pyserial numpy
   python3 scripts/power_capture.py --list
   python3 scripts/power_capture.py --port /dev/ttyACM0 --seconds 180
   ```
   On a Mac the port looks like `/dev/cu.usbmodem…`. 180 s covers about 8 measurement cycles.
6. **Energy:** `python3 scripts/device_energy.py`, or `make device-energy`. It writes
   `results/real/device_energy.json`; `make handoff` adds it to the summary.

### Better accuracy (optional)

- **Measured constants.** With a multimeter, measure the Uno's **AREF** pin (the internal reference while the
  sketch runs, nominally 1.1 V but ±10%) and its **5V** pin. Then run
  `python3 scripts/device_energy.py --vref <AREF> --vsupply <5V>`.
- **No multimeter.** Put a known resistor (e.g. 100 Ω) where the ESP32 was, capture 20 s to
  `results/real/power_cal.csv`, then run
  `python3 scripts/device_energy.py calibrate --csv results/real/power_cal.csv --load-ohms 100`. It prints the
  `--vref` to use.
- Either way, the **ratio** of envelope_ratio to time_only energy doesn't depend on these constants.

## What gets measured, and what doesn't

- **Measured:** whole-board power while computing features and the model, per window, and idle power. The
  incremental energy (active − idle) is also reported.
- **Not included:**
  - sensor acquisition, since the windows are stored rather than sampled;
  - shaft-speed estimation, since speed comes from the file's RPM, the paper's measured-speed mode;
  - any radio use.
- **Resolution:** with the 1.1 V reference and 1 Ω, one ADC step is about 1.07 mA. Each 1 ms reading averages
  ~4 conversions, and each block spans thousands of readings.
